# STR Solutions — Phase 3 Build Guide

Public website suite, static UI, no GSAP. This file is the spec your VS Code AI
extension should be given as context before it touches anything in this repo.

---

## 0 · Why the old build "looked like AI"

Worth naming precisely, because the fixes are mechanical.

| Tell | Was | Now |
|---|---|---|
| **Font** | Plus Jakarta Sans at `font-extrabold` | **General Sans** (Fontshare), headings capped at **600** |
| **Tracking** | `tracking-tighter` on everything | Optical: `-0.038em` on h1, `-0.028em` on h2–h4, normal on body |
| **Type scale** | `text-5xl sm:text-7xl lg:text-8xl` staircase | Fluid `clamp()` utilities — `.text-display`, `.text-heading`, `.text-subheading` |
| **Neutrals** | Tailwind slate (`#f8fafc`, `#64748b`) — the default blue-grey everyone ships | Warm ramp: paper `#F4F2EE`, ink `#09090A`, muted `#8A8A85` |
| **Eyebrows** | `bg-blue-100 text-blue-600 rounded-full` pills | `SectionIndex` — `01 // WHAT WE DO` in mono |
| **Cards** | Uniform grid, soft shadows, indigo glow | 1px-gap grids over a `--line` background; hairline is the *gap*, not a border |
| **Hover** | Shadow lift / scale-105 | Signal rule wipes in (`scale-x-0 → 100`), image un-desaturates |
| **Headings** | One weight, gradient keyword | Mixed-weight sentence: bold clause + `text-(--text-mute)` clause |
| **Sections** | Hero → 3 cards → testimonials → CTA | 9 sections with an inverted band mid-page as a reset |

The single highest-leverage change is the font. Reference site `iotlabbd.com`
runs General Sans 600 at `-1.37px` tracking; that is what makes it read as
designed rather than generated.

## 1 · Decisions locked this phase

1. **Dark-first.** `defaultTheme="dark"`, `enableSystem`, full light mode.
2. **7 services**, slugs generated by the same `slugify(title, {lower, strict})`
   the backend uses, so `lib/data.js` slugs and Mongo slugs cannot drift:

   `web-development · custom-software · mobile-applications · product-design ·
   graphics-design · architectural-visualization · digital-marketing`

   > ⚠️ This **drops** `cloud-devops` and `cybersecurity` from the backend enum
   > and **adds** graphics / visualization / marketing, which the assets in
   > `public/` clearly show STR actually sells. If those two are real services,
   > add them to the enum in §7 and to `lib/data.js` — nothing else changes.

3. **`Project.serviceTypes` is an array.** Multi-service tagging was in the
   brief and the current single-enum field cannot express it. Migration in §7.
4. **Logo on a white plate in dark mode.** `public/logo.png` is a dark-blue
   wordmark on transparency and sits at ~3.5:1 on `#09090A`. `dark:invert`
   would flatten the orange and green out of the identity. If the legacy folder
   has a knockout variant, drop it at `public/logo-invert.png` and swap the
   branch in `components/ui/Logo.jsx`.
5. **`public/footer.png`** (the SSLCommerz "Pay With" strip) sits in the footer
   on its own white plate in both themes — bank marks must never be recoloured.

**Client boundary rule:** only four files carry `"use client"`, and none of them
import `lib/data.js`. A single named import ships the whole module, so
`ProjectRail` imports labels from `lib/taxonomy.js`. Keep it that way — this is
the difference between a 12KB and a 90KB client bundle.

## 3 · Design law (give this section to the AI extension verbatim)

**Tokens.** Never write a hex or a Tailwind palette colour in a component.
Semantic tokens only:

```
--canvas --raised --raised-2 --line --line-soft --text --text-dim --text-mute --overlay
```

used as `bg-(--canvas)`, `text-(--text-mute)`, `border-(--line)`. Brand colours
are Tailwind theme colours: `bg-brand`, `bg-brand-hi`, `text-signal`, `text-leaf`.

**Typography.**

| Use | Class | Notes |
|---|---|---|
| Page h1 | `text-display` | clamp 2.6→6.5rem, weight 600, `-0.042em` |
| Section h2 | `text-heading` | clamp 1.9→3.4rem |
| Card / article h3 | `text-subheading` | clamp 1.35→1.9rem |
| Eyebrow, meta, index, timeline | `label-mono` | JetBrains Mono, 11px, `0.16em`, uppercase |
| Body | default | 0.9375rem in dense UI, 1.0625rem in ledes |

Never `font-bold` or `font-extrabold` on a heading. Never `tracking-tighter` —
the h-tags already carry optical tracking from `@layer base`.

**Layout.**

- Every route uses `.shell` for gutters. Do not invent `max-w-7xl mx-auto px-4`.
- Sections own their own `border-b border-(--line)` and vertical padding.
  `app/page.js` contains zero spacing classes — reordering is one line.
- Grids that need internal rules use `gap-px` over `bg-(--line)`, children on
  `bg-(--canvas)`. The gap *is* the hairline; no doubled borders at seams.
- Asymmetry is mandatory: 7/5 or 8/4 splits, offset rows (`lg:mt-24`), never
  `grid-cols-3` of equal cards.

**Forbidden.** Rounded pill badges · `shadow-*` on cards · gradient text on
headings · `rounded-xl/2xl` on structural containers · centred hero blocks ·
`backdrop-blur` on a header at `scrollY === 0` · emoji as icons.

## 6 · Phase 4 wiring (do not do this yet)

Each selector becomes one `fetch`. Signatures do not change.

```js
// lib/api.js
const BASE = process.env.NEXT_PUBLIC_API_URL;           // http://localhost:5000/api/v1

async function get(path, { revalidate = 300, tags = [] } = {}) {
  const res = await fetch(`${BASE}${path}`, { next: { revalidate, tags } });
  if (!res.ok) throw new Error(`${res.status} ${path}`);
  return (await res.json()).data;
}

export const getProjects = ({ service, limit } = {}) =>
  get(`/projects?${new URLSearchParams({
    ...(service && { serviceTypes: service }),
    ...(limit && { limit }),
  })}`, { tags: ["projects"] });
```

Then:

- `InquiryForm` → `POST /inquiries` with the exact field names already in the
  form (`senderName senderEmail phone serviceInterested budgetRange message`).
  The client validation there **mirrors** `validators/inquiry.validator.js`; it
  does not replace it.
- `Blog.content` and `Project.fullCaseStudy` currently go through
  `dangerouslySetInnerHTML` from our own authored strings. The moment they come
  from the admin editor, sanitise server-side (`isomorphic-dompurify` on the
  Node side, allow-list tags) before the prop is set. Three call sites, all
  marked with a comment.
- Add `revalidateTag("projects")` etc. to the admin mutation handlers.

## 7 · Backend migration — `serviceType` → `serviceTypes[]`

`str-backend/src/models/Project.js`:

```diff
-    serviceType: {
-      type: String,
-      required: true,
-      index: true,
-      enum: [
-        "web-development",
-        "mobile-app",
-        "ui-ux-design",
-        "custom-software",
-        "cloud-devops",
-        "cybersecurity",
-      ],
-    },
+    serviceTypes: {
+      type: [String],
+      required: true,
+      index: true,
+      validate: {
+        validator: (v) => Array.isArray(v) && v.length > 0 && v.length <= 4,
+        message: "A project needs between 1 and 4 service types",
+      },
+      enum: {
+        values: [
+          "web-development",
+          "custom-software",
+          "mobile-applications",
+          "product-design",
+          "graphics-design",
+          "architectural-visualization",
+          "digital-marketing",
+        ],
+        message: "{VALUE} is not a supported service type",
+      },
+    },
```

Add a read-compat virtual so any existing consumer keeps working:

```js
projectSchema.virtual("serviceType").get(function () {
  return this.serviceTypes?.[0] ?? null;
});
projectSchema.set("toJSON", { virtuals: true });
projectSchema.set("toObject", { virtuals: true });
```

`controllers/project.controller.js`:

```diff
-  allowedFilters: ["serviceType", "featured", "tags"],
+  allowedFilters: ["serviceTypes", "featured", "tags"],
```

`utils/ApiFeatures.js` must translate `?serviceTypes=web-development` into
`{ serviceTypes: { $in: [...] } }` for a comma-separated value — otherwise an
array field with a scalar filter silently does an exact-element match, which
happens to work for one value and breaks for two.

One-shot migration (run once, then drop the old field):

```js
await Project.collection.updateMany(
  { serviceType: { $exists: true } },
  [{ $set: { serviceTypes: ["$serviceType"] } }]
);
await Project.collection.updateMany({}, { $unset: { serviceType: "" } });
await Project.collection.createIndex({ serviceTypes: 1, featured: -1, displayOrder: 1 });
```

The compound index matters: the public list query filters on `serviceTypes` and
sorts on `featured, displayOrder`, and a sort on an unindexed prefix forces an
in-memory sort that fails at 32MB.

## 8 · Before you run it

```bash
cd str-frontend
npm install          # no new dependencies were added
npm run dev
```

`General Sans` loads from `api.fontshare.com` via `@import` in `globals.css`.
It works out of the box but is render-blocking. **Production upgrade:** download
the four `.woff2` weights, drop them in `public/fonts/`, and switch to
`next/font/local` in `app/layout.js` — worth roughly 120ms of LCP.

## 11 · Phase 5 hooks already in place

Nothing needs restructuring to add GSAP later:

- `Project.animationTrigger` (`fade-up` / `pinned-scroll` / `3d-tilt`) and
  `layoutStyle` are carried through to the case-study page unused.
- `metrics` in `lib/data.js` is pre-split into `value` + `suffix`, so a count-up
  only ever touches the number node — and `.nums` already forces tabular figures
  so it cannot reflow the row.
- The marquee is pure CSS; ScrollTrigger can take it over without markup changes.
- Section boundaries are already `<section>` elements with their own borders,
  which is exactly what `ScrollTrigger` wants as pin targets.
